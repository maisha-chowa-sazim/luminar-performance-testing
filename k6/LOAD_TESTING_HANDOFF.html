Load-testing overview

Merchandiser and Inventory users run independently. Each uses an assigned account and a reusable session.

Business flow

Merchandiser: Style → Techpack and file uploads → Sample → BOM → Pre-costing → Purchase order → Work order.

Senior Merchandiser: Approve the work order → Set SENT_TO_SUPPLIER → Confirm readiness.

Inventory: Claim a ready order → Receive all items through one GRN → Verify quantities, work-order status and receipt uniqueness.

Only work-order approval is included. Other approvals, QC and stock-entry creation are excluded.

Concurrency and handoff

Two ramping-vus scenarios run concurrently. A local coordinator assigns each ready order to one Inventory VU and saves its claim in a run ledger. Failed or uncertain receipt writes are recorded and never automatically retried or reassigned.

Named files pin their role allocation and steady period. Default 2-minute ramps, producer completion grace, Inventory drain, and setup authentication are additional. The 100-user profile requires provisioned distinct accounts. The supporting approval account runs inside Merchandiser VUs.

The report RPS field counts regular API requests only, excluding techpack, setup, and coordinator requests. It remains a whole-run elapsed-time rate; uploads and pauses still affect achieved API throughput.

Think time — simulated user pauses

Think time is the pause between user actions, such as reading a page or reviewing an order. We use random pauses to mimic real users and avoid sending requests continuously at machine speed. API response and file-upload times are additional.

ROLE_THINK_SCALE scales these pauses (default 1). Login navigation pauses are separate from authentication pacing and rate-limit cooldowns. Smoke disables them, limits each producer to one workflow and stops on workflow error. Empty Inventory polls wait 2 seconds.
